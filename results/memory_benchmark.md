# 다중 모델 메모리·처리량 실험 기록

RK3588 환경에서 여러 RKNN 모델을 동시에 운용할 수 있는지 검토한 기록이다. 메모리 값은 당시 개발 문서에 표기된 프로세스/시스템 관찰값이며, 동일 조건의 원시 측정 로그가 아니라 구성 간 상대 비교 자료로 사용한다.

| 모델 구성 | 클래스 구성 | 기록된 메모리 | 기록된 처리량 | 실행 상태 |
|---|---|---:|---:|---|
| YOLOv8n 1개 | 단일 전체 모델 | 1.6 GB | 13.x FPS | 유지 |
| YOLOv8s 1개 | 단일 전체 모델 | 1.7 GB | 11.x FPS | 유지 |
| YOLOv8s 1개 | 817 classes | 1.2 GB | 16.x FPS | 유지 |
| YOLOv8s 1개 | 822 classes | 1.2 GB | 16.x FPS | 유지 |
| YOLOv8s + YOLOv8n | 전체 모델 2개 | 2.8 GB | 12.x FPS | 프로세스 중단 관찰 |
| YOLOv8s + YOLOv8s | 전체 모델 2개 | 3.3 GB | 11.x FPS | 메모리 한계에 근접 |
| YOLOv8s + YOLOv8s | 817/822 classes 분할 | 2.8 GB | 15.x FPS | 유지 |
| 모델 3개 | 다중 구성 | 한계 초과 | 측정 중단 | 프로세스 중단 관찰 |

## NPU 사용률 기록

| 구성 | 코어별 기록 |
|---|---|
| YOLOv8n 단일 | 약 42% |
| YOLOv8s 단일 | 약 46% |
| 분할 YOLOv8s 2개 | 각 약 36% |

## 설계에 반영한 점

- 클래스 집합을 817/822로 나눈 두 모델은 전체 모델 두 개보다 메모리와 처리량이 유리한 기록을 보였다.
- 세 모델 동시 운용은 안정성 측면에서 제외했다.
- 최종 소스 스냅샷은 단일 모델을 기본 경로로 두고, 공유 메모리에 보조 상태 필드를 남겨 다중 모델 실험의 확장 지점을 유지했다.

이 결과는 특정 배포 구성을 보증하는 용량 계획표가 아니라, 모델 수와 클래스 분할을 결정할 때 사용한 엔지니어링 기록이다.
