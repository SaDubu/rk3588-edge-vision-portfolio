# 모델 비교 및 RKNN 전환 기록

이 문서는 개발 당시 비교표와 작업 기록을 포트폴리오용으로 다시 정리한 것이다. 서로 다른 데이터 규모와 실행 경로의 수치를 하나의 벤치마크처럼 합치지 않고, 기록된 조건별로 분리했다.

## 프로젝트 목표와 측정값의 구분

| 구분 | 지표 | 값 | 해석 |
|---|---|---:|---|
| 설계 목표 | 상품 인식률 | 98% 이상 | 목표값이며 아래 실험 전체의 달성 결과가 아님 |
| 설계 목표 | MOTA | 70 이상 | 추적기 개발 목표이며 최종 SMOF 측정값이 아님 |
| 선행 추적 실험 | MOTA | 약 30% | SORT 계열을 검토하던 초기 관찰값 |
| 통합 경로 기록 | 평균 지연 | 약 180 ms | 당시 RKNN 추론·후처리 경로에서 기록 |
| 통합 경로 기록 | 처리량 | 약 5 FPS | 위 지연 측정과 함께 남은 근사값 |

선행 추적 실험의 별도 MOT15 평가 결과는 [CNN-SORT Customization](https://github.com/SaDubu/CNN_SORT_Customization)에 독립적으로 보존했다. 두 프로젝트의 수치를 합쳐 최종 성능으로 표현하지 않는다.

## YOLOv5s와 YOLOv8s 처리량 비교

| 입력 데이터 기록 | YOLOv5s | YOLOv8s | 당시 판단 |
|---|---:|---:|---|
| 커스텀 이미지 24,643장 | 23–24 FPS | 12–13 FPS | 처리량은 v5s가 우세 |
| COCO 이미지 118,287장 | 22 FPS | 13 FPS | 데이터 규모가 커져도 같은 경향 |

이 표는 개발 기록에 남은 FPS 비교를 옮긴 것이다. 커밋된 원시 타이밍 로그는 없으므로 하드웨어·런타임·양자화 설정까지 통제된 재벤치마크 결과로 확대 해석하지 않는다.

## 엣지 보드와 PC의 인식률 기록

| 모델 | 실행 환경 | 기록된 인식률 |
|---|---|---:|
| YOLOv8s | RK3588 엣지 보드 | 98.7% |
| YOLOv8n | RK3588 엣지 보드 | 96.4% |
| YOLOv8s | PC | 96.4% |
| YOLOv8n | PC | 96.4% |

위 값은 당시 문서에 기록된 비교값이다. 표본 구성과 계산 스크립트가 현재 공개 스냅샷에 함께 남아 있지 않아, 포트폴리오의 대표 검증 지표로 사용하지 않고 설계 판단의 참고 기록으로만 제시한다.

## RKNN 후처리 문제와 수정

YOLOv8s를 RKNN으로 변환한 초기 경로에서는 24,643개 입력 중 검출이 기록된 경우가 200개에 그쳤다. 원인은 RKNN 출력 텐서의 분할 구조를 기존 후처리가 그대로 다루지 못한 것이었다.

수정 방향은 다음과 같았다.

1. 출력 branch별 box와 class confidence를 분리한다.
2. 각 scale의 텐서를 동일한 좌표 체계로 복원한다.
3. 후보를 병합한 뒤 confidence filtering과 NMS를 적용한다.
4. C++ IPC 형식인 `x1, y1, x2, y2, confidence, class_id`로 직렬화한다.

수정 후 검출이 정상화되었고 이 흐름은 `src/python/yolo8_rknn.py`와 `src/python/ipc_python.py`에 남아 있다. 단, 200/24,643은 수정 전 장애 규모를 보여주는 값이지 수정 후 인식률이 아니다.

## 결론

- 단일 모델 처리량만 보면 당시 비교에서는 YOLOv5s가 유리했다.
- 통합 구현은 상품 인식 기록과 RKNN 배포 경로의 수정 용이성을 고려해 YOLOv8 계열을 계속 사용했다.
- NPU 전환의 핵심 작업은 모델 변환 자체보다 출력 텐서 구조에 맞춘 후처리와 C++ 경계의 데이터 계약을 맞추는 일이었다.
- 최종 포트폴리오에서는 근거가 남은 상품 테스트 집계를 대표 결과로 사용한다.
