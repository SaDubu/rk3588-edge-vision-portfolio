# 공개 범위와 익명화 기준

포트폴리오에서는 구현 판단과 기술적 근거를 보존하되, 조직·협업사·개인·내부 데이터가 특정되지 않도록 공개 범위를 다시 구성했다. 원본 저장소 자체를 수정하지 않고 별도의 공개용 스냅샷을 만든 이유도 여기에 있다.

## 공개한 내용

- 최신 기본 경로에서 실제로 호출되는 C++ 파이프라인과 Python RKNN 연동 코드
- 특정 조직을 식별하지 않는 시스템 구조와 설계 의사결정
- 개발 기록에 남은 실험 조건과 수치 중 설명 가능한 집계값
- 브랜드·매장·사용자를 식별하지 않는 추적 결과 이미지
- 원본 경로, 기준 커밋, 파일 해시를 통한 출처 추적 정보

## 일반화하거나 제외한 내용

| 위험 범주 | 처리 기준 |
|---|---|
| 회사·협업사 명칭 | 포트폴리오 본문에서 삭제하고 역할 중심 표현으로 일반화 |
| 사업 계획·납품 맥락 | 기술 문제 정의에 필요한 범위만 남기고 조직 관계와 일정은 제외 |
| 개인 식별 정보 | 이메일, 사용자 계정, 개발 장비 경로와 전체 Git 이력 제외 |
| 학습 데이터 | 이미지, 영상, 프레임별 로그와 전체 상품 분류표 제외 |
| 모델 자산 | 학습 가중치와 RKNN/ONNX 변환 산출물 제외 |
| 실행 산출물 | ELF 바이너리, `*.pyc`, 캐시, IDE/복구 파일 제외 |
| 성능 주장 | 목표와 측정값을 분리하고, 원시 근거가 없는 수치는 당시 기록으로 표시 |


프로젝트 자체 라이선스를 결정하기 전에는 이 저장소를 포트폴리오 검토용 소스 스냅샷으로 취급한다.
